Part 1 · covers the recsys textbook foundations

It all starts with the interactions matrix 6 min live

Strip away the buzzwords and a recommender is a function over one table: rows are users, columns are items, and each cell is an interaction - a purchase, a rating, a click, a watch. Almost every algorithm is a different way to guess the blank cells.

LiveExplicit vs implicit feedback - the choice that shapes everything3 min▶

What goes in the cells changes the whole approach:

  • Explicit feedback - the user told you (a 1-5 star rating, a thumbs up). Rich but rare; most users never rate. The Netflix Prize was on explicit star ratings.
  • Implicit feedback - you inferred it from behaviour (bought, clicked, watched, added-to-cart). Abundant and honest, but one-class: a blank means "did not interact", not "disliked". Almost all e-commerce recsys is implicit - Kirana included.
  • Why it matters: implicit data needs different models (weighting confidence, not predicting a rating) and different evaluation (ranking, not rating error). We will feel this in b6 and b8.
Real world

The industry moved from stars to signals. Netflix famously started with a 5-star prediction contest, then shifted to implicit signals - what you actually watch, how long, when you bail - because behaviour beats stated preference. Amazon never needed stars: a purchase is the strongest signal there is. When you design Kirana's recommender, purchases and clicks are your gold.

Self-studyBuild the matrix from transactions (pandas)2 min read▶

Real transaction logs are long and thin (one row per purchase). A pivot_table turns them into the user-item matrix:

★ Run it now (Python) - transactions to matriximport pandas as pd # Kirana transaction log: one row per purchase tx = pd.DataFrame({ "user": ["u1","u1","u2","u2","u3","u3"], "item": ["Yoga Mat","Dumbbells","Yoga Mat","Protein","Blender","Cookbook"], "qty": [1, 1, 1, 2, 1, 1], }) # users x items interaction matrix (implicit: 1 = bought) mat = tx.pivot_table(index="user", columns="item", values="qty", aggfunc="sum", fill_value=0) mat = (mat > 0).astype(int) # binarize to implicit signal print(mat)

That mat - a sparse users x items table - is the input to nearly everything from here.

Build Kirana's interactions matrix ★ 12 min · everyone builds

Turn a raw transaction log into the users x items matrix every later model consumes.

In a notebook, load a transaction log (use the sample below, or export your own non-confidential order history to CSV).

Pivot it to a user-item matrix and binarize to an implicit signal (1 = interacted).

Inspect sparsity - the fraction of cells that are non-zero. Real recsys matrices are 99%+ empty; that sparsity is the whole challenge.

Save the matrix. It is the input to b2 through b6.

★ Run it now (Python) - matrix + sparsityimport pandas as pd, numpy as np mat = tx.pivot_table(index="user", columns="item", values="qty", aggfunc="sum", fill_value=0) mat = (mat > 0).astype(int) density = mat.values.sum() / mat.size print(f"shape {mat.shape}, density {density:.1%} (real stores are far sparser)")
Sparsity is the point A store with a million users and a hundred thousand items has a matrix that is essentially all blanks. Every algorithm ahead is a strategy for predicting those blanks well without needing them filled - which is why you store it sparse (scipy CSR), never as a dense array.

Ship the popularity baseline ★ 8 min · build your own

Before any clever model, build the baseline it has to beat. Popularity is three lines, ignores the user entirely, and is shockingly hard to beat on cold traffic - which is exactly why you measure against it.

Count how many users interacted with each item.

Recommend the top-N most popular items the user has not already got.

Keep it - in b8 you will measure every personalized model against this line, and in b3 you will watch a personalized algorithm leave it behind.

★ Run it now (Python) - popularity baselinedef popular_for(user, mat, n=3): pop = mat.sum(axis=0).sort_values(ascending=False) # item -> #buyers already = mat.columns[mat.loc[user] > 0] recs = [it for it in pop.index if it not in already][:n] return recs print(popular_for("u1", mat)) # same list for everyone - that is the weakness
Real world

Never skip the baseline. Teams routinely ship a complex model that, on measurement, barely beats "just show the bestsellers". Popularity is the honesty check: if your personalized recommender cannot beat it on the metrics in b8, it is not earning its complexity. It is also your cold-start fallback for brand-new visitors with no history at all.

Check yourself

Three questions before you go 🎯 ◐ 90 seconds

1 · What is the interactions matrix?

Rows are users, columns are items, cells are purchases/clicks/ratings. Almost every algorithm is a different way to fill the blank cells.

2 · Your data is purchases and clicks, with no ratings. That is...

Behaviour is implicit, one-class feedback. It is abundant and honest, but needs confidence-weighted models and ranking metrics, not rating-error prediction.

3 · Why build the popularity baseline first?

Popularity ignores the user and is surprisingly hard to beat. If your fancy model cannot beat it (b8), it is not earning its complexity - and it covers brand-new visitors.
