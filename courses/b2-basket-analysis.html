Part 0

The analyst's first move

Long before a data scientist trains a model, an analyst looks at the receipts and asks a plain question: which items travel together in the same basket? That is market basket analysis, and its answers - "people who buy a yoga mat tend to buy a strap" - become the "frequently bought together" shelf on day one, with no machine learning at all. Tonight we compute the three numbers that grade every co-purchase, then run the Apriori algorithm that made this practical at scale. Everything runs on Kirana, our running store, so the pipeline stays one continuous story from b1's matrix onward.

Part 1 · covers the association-rule canon

Support, confidence, lift 6 min live

An association rule is a statement like {Yoga Mat} -> {Strap}: "baskets with a mat also tend to have a strap". Three numbers grade it, and each answers a different question. Get these three and you can read any rules table in the field.

LiveA worked Kirana example, by hand3 min▶

Say Kirana has 10 baskets. A yoga mat appears in 4 of them; a strap appears in 5; both appear together in 3. Now the three numbers fall out:

  • Support{Mat, Strap} = 3 / 10 = 0.30. Both items show up together in 30% of all baskets - common enough to bother with.
  • Confidence {Mat} -> {Strap} = 3 / 4 = 0.75. Of the 4 mat baskets, 3 also had a strap - a strong conditional rate.
  • Lift = confidence / P(Strap) = 0.75 / (5/10) = 0.75 / 0.50 = 1.5. Mat buyers grab a strap 1.5x more than the average shopper does.
Real world

Why lift saves you from a classic trap. Bags appear in almost every Kirana basket, so any rule {X} -> {Bag} will show sky-high confidence - not because X drives bags, but because everything does. Lift divides that confidence by the bag's own baseline, collapsing it back toward 1. That is how the analyst avoids recommending the obvious bestseller to everyone and finds the pairings that are genuinely surprising.

Self-studyDirection, thresholds, and the caveats2 min read▶

Three things that trip up first-time analysts:

  • Rules have direction. {Mat} -> {Strap} and {Strap} -> {Mat} share the same support but usually differ in confidence, because the two items appear in different totals. Always read the arrow.
  • Set a support floor. A rule seen in 2 baskets out of a million is noise. Analysts set a minimum support so rare accidents do not surface as recommendations.
  • Correlation, not cause. A high-lift rule says two items co-occur, not that one causes the other. It is a great candidate for a shelf or a test, not a proven mechanism.

These three numbers are the whole vocabulary of basket analysis. The only hard part left is computing them at scale - which is where Apriori comes in.

Part 2 · covers Agrawal & Srikant (1994)

Apriori: finding frequent itemsets without brute force 5 min live

With 100 items there are over a trillion possible itemsets. You cannot count support for all of them. Apriori (Agrawal & Srikant, 1994) is the classic trick that makes it tractable, and it rests on one beautifully simple property.

LiveThe downward-closure idea, in one line3 min▶

Apriori's engine is the downward-closure property: if an itemset is infrequent, every superset of it is also infrequent. If {Mat, Strap} appears in too few baskets to clear your support floor, then {Mat, Strap, Bag} can only appear in fewer - so there is no point ever counting it.

  • Start with single items that clear the support floor.
  • Combine them into pairs, but only pairs built from already-frequent singles.
  • Count support for those pairs; keep the frequent ones; grow to triples the same way. Stop when nothing frequent remains.
  • From every frequent itemset, generate rules and score each by confidence and lift.
Why it still matters Deep models came later, but Apriori is 30 years old and still the honest first pass: it is fast, fully explainable ("we show these together because 62% of mat baskets include a strap"), and needs no training. For a "frequently bought together" shelf it is often all you need.
Demo 1 of 2

Rules by hand with pandas ★ 12 min · everyone builds

Compute support, confidence and lift yourself from Kirana's baskets - no library - so the three numbers are never a black box. The trick is a co-occurrence matrix from mat.T.dot(mat).

Build a basket matrix (baskets x items, 1 = item in basket) - the same shape as b1's mat, but one row per receipt.

Get pair co-occurrence counts with mat.T.dot(mat) - each cell is how many baskets hold both items.

Turn counts into support, confidence and lift for every directed pair.

Sort by lift and read the top rules.

★ Run it now (Python) - support, confidence, lift by handimport pandas as pd, numpy as np # Kirana baskets: one row per receipt (implicit, 1 = item in basket) baskets = [ ["Yoga Mat","Strap","Bag"], ["Yoga Mat","Strap"], ["Yoga Mat","Strap","Bottle"], ["Yoga Mat","Bag"], ["Strap","Bottle"], ["Bottle","Bag"], ["Yoga Mat","Strap","Bottle","Bag"], ["Strap","Bag"], ["Bottle"], ["Yoga Mat","Bottle"], ] items = sorted({i for b in baskets for i in b}) mat = pd.DataFrame([{i: int(i in b) for i in items} for b in baskets]) n = len(mat) # number of baskets co = mat.T.dot(mat) # co-occurrence counts (item x item) sup1 = mat.sum() / n # single-item support rules = [] for a in items: for b in items: if a == b: continue sup_ab = co.loc[a, b] / n # support of the pair {a,b} conf = co.loc[a, b] / co.loc[a, a] # P(b | a) lift = conf / sup1[b] # vs b's baseline if co.loc[a, b] > 0: rules.append((a, b, round(sup_ab,2), round(conf,2), round(lift,2))) rules = pd.DataFrame(rules, columns=["A","B","support","confidence","lift"]) print(rules.sort_values("lift", ascending=False).head(8).to_string(index=False))
Real world

Read the top of that table like the analyst does. {Yoga Mat} -> {Strap} lands high on lift, so it earns a spot on the mat's product page. A rule pointing at Bag will show decent confidence but lift near 1, because Bag is in half the baskets anyway - exactly the coincidence lift is built to expose. You just did, in 20 lines, the analysis that fills a "frequently bought together" shelf.

The same rules with mlxtend Apriori ★ 10 min · build your own

In production you reach for a tested library. mlxtend gives you apriori for frequent itemsets and association_rules for the graded rules - the same numbers you just computed, on a one-hot basket frame.

One-hot the baskets into a boolean frame (TransactionEncoder, or reuse the mat from Demo 1 as booleans).

Run apriori with a min_support floor to get frequent itemsets.

Pass those to association_rules with a lift threshold, then sort by lift.

Compare the top rows to your hand-built table - they match.

★ Run it now (Python) - mlxtend apriori + association_rules# pip install mlxtend from mlxtend.frequent_patterns import apriori, association_rules # reuse Demo 1 baskets: one-hot boolean frame (baskets x items) onehot = mat.astype(bool) # frequent itemsets that clear a 20% support floor freq = apriori(onehot, min_support=0.2, use_colnames=True) # graded rules, keep only the ones bought together more than chance rules = association_rules(freq, metric="lift", min_threshold=1.0) cols = ["antecedents","consequents","support","confidence","lift"] out = rules[cols].sort_values("lift", ascending=False) print(out.head(8).to_string(index=False))
Read {A} -> {B} by lift, always Sort by lift, then sanity-check support so you are not acting on a two-basket fluke. mlxtend's antecedents is the {A}, consequents is the {B}. This same frequent-itemset engine scales to real logs with a scipy-sparse frame - the API does not change, only the data size does.

Check yourself

Three questions before you go 🎯 ◐ 90 seconds

1 · What does lift > 1 for {A} -> {B} tell you?

Lift is confidence divided by B's baseline rate. Above 1 means buying A genuinely raises the odds of B; at 1 they are independent; below 1 they repel.

2 · A rule has 0.9 confidence but lift of 1.0. What is going on?

When B appears in most baskets anyway, confidence to B is high for any A. Lift near 1 exposes that the pairing is a coincidence, not a driver - exactly the trap lift is designed to catch.

3 · What does Apriori's downward-closure property let you do?

If an itemset is infrequent, every larger set containing it is also infrequent. Apriori uses that to skip counting the vast majority of candidate itemsets.
